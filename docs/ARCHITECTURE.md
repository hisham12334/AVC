# Architecture

## Decision record

| Concern                        | Phase 0 choice                                                                 | Rationale and trade-off                                                                                                                                                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Staff web                      | React 19 with Vite and TypeScript                                              | Supports a task-focused, responsive staff UI. Static build is served by the API, so it is not a second deployed service. Client rendering needs explicit accessibility and loading-state discipline.                                              |
| Backend                        | Fastify 5 with TypeScript on Node 24                                           | Small, typed HTTP foundation with structured Pino logging and straightforward command endpoints. Less framework convention than NestJS, so module rules must be enforced by review and tests.                                                     |
| Data                           | PostgreSQL 17 or 18 with explicit SQL migrations and `pg`                      | Transactions, constraints and audit queries fit the job lifecycle. SQL avoids ORM abstraction early; data access conventions must be documented as modules grow. Local validation used 18.                                                        |
| Customer and technician mobile | Future React Native / Expo candidate, not installed now                        | Shared TypeScript contracts may help; native camera, upload and encrypted offline storage need a proof of concept before commitment. Responsive approval web flow can arrive earlier. Flutter remains an alternative if device testing favors it. |
| Media                          | Future private object storage with signed upload/download URLs                 | Large photos/videos do not belong in PostgreSQL. Provider, retention, virus scanning and residency remain open.                                                                                                                                   |
| Background work                | Future PostgreSQL-backed job queue in the same deployment                      | Enough for Zoho/notification retries initially; no broker or second worker service until throughput requires it. Durable outbox and idempotency are required before external calls.                                                               |
| Auth                           | Future OIDC/OAuth identity provider plus server-side role and job-scope checks | Avoids writing password/OTP security infrastructure. Provider and customer-link verification are unresolved. The current shell is deliberately unauthenticated and contains no business data.                                                     |
| Testing                        | Vitest for unit/API tests; PostgreSQL integration tests in the next milestone  | Fast Phase 0 feedback. Database and external integration tests need local/CI fixtures; no fake Zoho success path.                                                                                                                                 |
| Delivery                       | One API process serving built web assets, one PostgreSQL database              | Keeps deployment simple. CI checks formatting, lint, types, tests and build. Production deployment target, secrets service and release process remain open.                                                                                       |

## Boundaries

The modular monolith separates Identity, CRM/Fleet and Jobs/Intake in Milestone 1A; DVI/Media, Estimates/Authorization, Workshop/Logistics/QC, Finance/Zoho and Communications remain future boundaries. The job card is the operational aggregate. Persist events and later financial snapshots rather than deriving evidence from mutable labels. See `DOMAIN_MODEL.md`.

The API accepts a `TokenVerifier` interface. The deployed implementation fails closed because AVC has not selected an OIDC provider. Tests inject a verifier for invented subjects and exercise role checks against PostgreSQL staff records. No browser sign-in or live identity integration is claimed. The PWA caches only static build assets and icons, never API responses or navigations.

## Security and operations

Configuration is validated at startup. Logs are structured and redact authorization/cookie headers; future modules must not log tokens, customer documents, signatures or media URLs. Readiness queries PostgreSQL. Database migrations are checksummed and serialized with an advisory lock. TLS, backups, retention, OIDC, storage encryption and UAE data-handling review must be established before production.
